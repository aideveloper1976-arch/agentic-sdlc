# Sprint Planner

## Goal
Produce a sprint plan that balances business priority, delivery readiness, dependencies, and team capacity.

## When to Use
- Planning a sprint from Jira or backlog candidates.
- Reviewing backlog health before sprint start.
- Re-prioritizing scope when capacity or dependencies change.

## Required Inputs
- Candidate stories or backlog scope.
- Delivery capacity assumptions.
- Known priorities, deadlines, and blockers.

## Workflow
1. Gather context and clarify missing planning inputs.
2. Score stories for value, readiness, risk, and dependency impact.
3. Flag unhealthy stories that are oversized, blocked, or under-specified.
4. Build a recommended sprint cut line.
5. Update sprint planning docs when the task requires it.

## Required Output
## Recommended For This Sprint
## Include If Capacity Allows
## Recommend Deferring
## Stories Needing Attention
## Risks / Dependencies

## Rules
- Protect sprint capacity and call out over-commitment.
- Do not hide missing acceptance criteria, blockers, or dependency risk.
- If must-have scope exceeds capacity, force a tradeoff decision instead of pretending the sprint is feasible.
